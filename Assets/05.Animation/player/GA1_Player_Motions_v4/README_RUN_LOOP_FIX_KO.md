# 기존 Run 복원 + 마지막/첫 프레임 연결 수정

사용자가 요청한 **이전 v4의 8프레임 달리기**로 되돌렸습니다. 이전 8개 PNG 파일은 파일 해시까지 동일하게 보존했습니다. 마지막 공중 자세에서 첫 착지 자세로 넘어가는 구간에만 새 연결 그림 2장을 추가했습니다.

재생 순서: **기존 1~8번 → 연결 A → 연결 B → 기존 1번**.

직전 수정본의 팔다리 분리·관절 방식은 이 Run 클립에서 사용하지 않습니다. 첫 프레임, 1~8번의 외형과 순서, 다른 동작의 프레임은 유지합니다.

## 기존 프로젝트에 적용

1. 교체용 ZIP의 `GA1_Player_Motions_v4` 내용을 기존 Unity `Assets` 안의 동일 폴더에 덮어씁니다. 기존 `.meta` 파일과 `Generated` 폴더는 유지합니다.
2. 컴파일이 끝나면 **Tools > GA1 > Build Player Motions v4**를 엽니다.
3. PPU와 SpriteRenderer Path를 기존 설정으로 지정합니다. 기본값은 200, 빈 경로입니다.
4. **Update Run Only**를 누릅니다. 기존 `Generated/Clips/Player_Run_v4.anim`이 같은 참조를 유지하면서 갱신됩니다.

이 도구는 `Motions.json`에 지정된 Run 10장만 사용합니다. 직전 20프레임 수정본을 설치했다면 폴더에 남아 있는 `Run_10.png`~`Run_19.png`는 이번 클립에서 사용되지 않습니다. 폴더의 모든 이미지를 새 애니메이션에 드래그하지 말고 위 생성 버튼을 사용하세요.

아직 v4 전체 팩을 넣지 않았다면 수정된 전체 팩을 먼저 넣고 **Build Motion Assets**를 실행합니다.

## 타이밍

전체 주기는 기존과 같은 **0.5초**입니다. 기존 첫 7장은 각각 0.0625초 표시합니다. 마지막 원화와 연결 A, B는 각각 약 0.020833초 표시합니다. 기존 마지막 원화의 0.0625초 구간을 이 세 장에 나눠 배정한 것입니다.

Unity 클립의 타임라인은 48fps를 사용하지만 모든 그림을 같은 길이로 표시하지는 않습니다. `Motions.json`과 생성 도구에 정확한 표시 시간이 들어 있습니다. 10장의 그림에 단순히 일정한 fps만 적용하면 이번 타이밍과 달라집니다.

## 크기와 반복

- 프레임: 512×512, 공통 PPU 200 기본값.
- Pivot: `(0.5, 0.19921875)`.
- 시트: 5열 × 2행, 2560×1024. 좌상단부터 오른쪽 순서.
- 첫 원화 8장 변경 없음, 나머지 91개 모션 프레임 변경 없음.
- 미리보기 프리팹에서 Run만 반복하려면 Auto Advance를 끄고 Motion을 Run으로 선택합니다.

## 제작 자료와 검증

`Source/RunBoundary/Original`은 이전 8장 원본입니다. 연결 원화만 내장 이미지 생성 기능으로 제작했으며 프롬프트는 `Source/RunBoundary/prompt.json`에 있습니다. `Source/build_run_boundary.cjs`는 원본 8장을 그대로 복사하고 연결 2장의 크기·좌표를 맞춰 시트를 출력합니다.

기존 원본의 파일 해시, 시트와 개별 프레임의 픽셀 일치, 투명 여백 및 타이밍을 검사했습니다. Unity Editor에서의 컴파일과 실제 게임 재생은 이 환경에서 실행하지 못했습니다.
