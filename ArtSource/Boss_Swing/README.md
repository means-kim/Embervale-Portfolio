# Boss Swing

설산 거인이 Slam과 반대쪽 팔로 가슴 앞을 가로질러 휘두르는 8프레임 공격입니다.
기준 Idle에서 화면 오른쪽에 크게 보이는 앞팔이 공격 팔입니다.
작은 화면 왼쪽 팔은 낮게 두고, 오른쪽 어깨에서 시작한 앞팔이 왼쪽으로 휘둘러집니다.

## 최종 결과물

- 시트: `Assets/04.Sprites/Boss/Boss_Swing.png`
- 클립: `Assets/05.Animation/Boss/Boss_Swing.anim`
- RGBA PNG 2048×1024, 4열×2행, 셀 512×512, 8프레임
- Bottom Center 피봇 `(0.5, 0)`, 픽셀 피봇 `(256, 0)`, PPU 50
- Max Size 2048, Bilinear, Mipmap 비활성화
- 순서: 위 행 왼쪽부터 0–3, 아래 행 왼쪽부터 4–7
- 프레임 0과 7은 기존 `Boss_Idle_0` 픽셀을 그대로 사용합니다.
- 모든 프레임에서 알파가 0보다 큰 픽셀 기준 하단 여백은 0px입니다.
- 그림의 위쪽과 양옆에 투명 여백이 있고, 손이나 얼음 결정이 셀 밖으로 잘리지 않습니다.

Animator 상태/전이, 공격 판정, VFX/SFX는 전투 구현 시 연결할 항목입니다.
공격 판정 연결 시 0.6–0.8초 구간을 시작 기준으로 사용할 수 있습니다.

## 제작 과정과 정렬

내장 ImageGen으로 기존 Idle, Walk, Slam을 참조했습니다.
초안에서 공격 팔이 바뀌는 포즈를 발견하여 수정했고, 마지막 휘두르기 포즈는
팔 연결이 올바른 프레임 4를 바탕으로 별도 생성한 뒤 프레임 5에 조립했습니다.
최종 조립은 이전에 선택한 코드 방식으로 수행했습니다.

- 시트의 생성 포즈는 Idle의 높이를 기준으로 같은 배율로 정규화했습니다.
- 별도 생성된 프레임 5는 앞발 크기와 몸 높이에 맞춰 실제 그림 높이 350px로 정규화했습니다.
- 접지선 Y는 모든 셀 바닥에 맞췄습니다.
- 앞발 중심 X도 기준에 맞췄지만, 프레임 2는 뒤로 뻗은 손의 잘림을 피하려고
  셀 안쪽으로 17px 이동했습니다. 따라서 프레임마다 발의 X가 완전히 고정된 시트는 아닙니다.
- 생성 이미지의 알파 16/255 미만 미세 잔상을 정리한 뒤 Lanczos 리샘플링을 적용했습니다.
- 기존 이미지, 클립, 메타데이터와 Animator Controller는 해시 비교로 변경 없음을 확인했습니다.
