# AirBoss 한팔 얼음 시전 — 실제 스프라이트 수정 v02

2026-10-04. 사용자가 최고점에서 잠시 멈추고 팔을 올리는 구간부터 내리기까지를 더 길게 요청했다. 앞선 응답은 미리보기의 프레임별 재생 시간만 바꾼 잘못된 적용이었다. **이번 v02는 PNG 시트의 셀 구성과 자세 그림을 실제로 바꾼 결과물**이다.

## 변경

전체 32프레임을 유지하고 올리기·유지·내리기를 기존 17장에서 23장으로 늘렸다. 기존 자세 사이에 6장의 실제 그림을 내장 imagegen으로 추가했다. 나머지 26셀은 채택된 v01 그림을 픽셀 그대로 재사용하여 연결했다. 그림 전체를 이동하거나 변형하여 중간 자세를 흉내 내지 않았다.

| 구간 | v01 | v02 | 12 FPS 비교 |
|---|---|---|---|
| Idle 시작 | 00 | 00 | 동일 |
| 올리기 | 01~08 · 8장 | 01~10 · 10장 | 0.667 → 0.833초 |
| 최고점 유지 | 09~12 · 4장 | 11~17 · 7장 | 0.333 → 0.583초 |
| 내리기 | 13~17 · 5장 | 18~23 · 6장 | 0.417 → 0.500초 |
| 앞부분 합계 | 17장 | 23장 | 1.417 → 1.917초 |
| 후행·복귀 | 18~30 · 13장 | 24~30 · 7장 | 1.083 → 0.583초 |
| Idle 끝 | 31 | 31 | 동일 |

- 같은 FPS에서 앞부분은 약 35.3% 길어지고, 최고점 구간은 75% 길어진다.
- **전체 장수와 FPS가 같으면 총 재생 시간은 같다.** 앞부분에 프레임을 더 배분한 만큼 복귀 구간이 짧아진다. 총 길이를 늘렸다는 의미가 아니다.
- 새 그림: v02의 03·07(상승 중간), 13·14·15(최고점에서 팔을 유지하고 천 끝만 조금 움직임), 20(하강 중간).
- 생성 후보 19번은 그림상 손이 v01의 14번보다 낮아, 최종 v02 20번에 배치해 역행을 피했다.
- 모든 셀의 출처는 [프레임 대응표](frame_map_v02.json)를 따른다.

## 검증 범위

- [Unity 실제 조회](unity_validation_v02.json): 두 시트 각16개, 총32개 Sprite, 이름·Rect·Pivot·PPU·텍스처 크기 확인.
- [픽셀 검증](validation_v02.json): 개별 셀과 시트 재추출 일치, 재사용 26셀 원본 일치, v01의 전체 픽셀 해시 불변, 양 끝 Idle 일치.
- 새로운 그림의 요청 해상도는1024×1024, 실제 생성 원본은1254×1254. 전체 캔버스만1024로 균등 정규화했다. 기존1024셀은 재리사이즈하지 않았다.
- 32프레임 접촉 시트와 새 그림 확대를 정적으로 비교했다. HTML 비교 자료를 제공하지만 브라우저의 실제 재생, Unity 게임 재생·최종 사용자 승인은 미검증이다.
- [알파 여백 측정](alpha_border_v02.json): 기존과 같이 사방64px 밖에 alpha1~2/255 미세 픽셀이 남아 있다. alpha>2의 그림은64px 안에 있으나 **모든 alpha>0 완전 투명 여백 기준은 미충족**이다. 생성 alpha를 보존했다.
