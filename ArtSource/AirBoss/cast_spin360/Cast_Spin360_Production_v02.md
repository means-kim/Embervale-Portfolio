# Cast_Spin360 v02 — 정면 유지 평면 회전 24장

2026-10-01 최신 사용자 요청: 정면 모습이 유지된 채 화면 안에서 몸이 옆으로 눕고, 거꾸로 뒤집혔다가 돌아오는 평면 회전으로 수정한다. 총 24장 멀티 스프라이트와 관련 지침만 제작·수정한다. Animation Clip·Animator·씬·프리팹·게임 코드는 생성하거나 변경하지 않는다.

제작 결과: 24개 셀과 16+8장 시트, Unity Multiple 총 24개·PPU 24·Center를 확인했다. 전 셀 사방 64px 여백과 시트 재추출 RGBA 일치를 통과했다. [최종 채택 순서·검증 기록](../../../Docs/Boss/AirBoss/AirBoss_Cast_Spin360_v02.md)을 따른다. 아래 각도표는 초기 생성 목표이며 최종 16~17은 왼쪽 수평 자세 부근에서 손목·천의 후행이 달라지는 두 그림이다. 실제 재생은 검증하지 않았다.

## 회전과 디자인

- v01의 세로축 회전은 과거 이력으로 보존한다. v02부터 화면에 수직인 축을 중심으로 정면을 유지하는 360도 평면 회전을 적용한다. 측면·후면으로 바뀌지 않는다.
- 시계 방향을 제작 방향으로 선택한다. 위쪽 머리 → 오른쪽 머리(90도) → 아래쪽 머리(180도) → 왼쪽 머리(270도) → 위쪽 머리(360도) 순서다. 방향은 작업 선택이며 사용자 확정 사항은 평면 회전과 24장이다.
- 고정 회전 중심은 셀 (512,512). 가면·흉갑이 셀 안에서 원호를 따라 이동하는 것은 의도한 평면 회전이다. 외곽 중심에 맞춰 그림을 다시 정렬하지 않는다.
- 가면 정면·푸른 눈·높은 목 갑옷·흉갑·양손과 비대칭 천 부착점을 유지한다. 원근 축소·뒤통수·등을 추가하지 않는다. 천 끝은 몸통보다 늦게 따라오고 팔꿈치·손목은 회전과 감속에 반응한다.
- 마스터 PNG를 기계적으로 회전한 복제본을 프레임으로 사용하지 않는다. 각 포즈를 마스터와 주변 포즈를 참조해 새로 그린다. 좌우 반전·역순 복제·전신 반투명 중첩·프레임별 축소를 금지한다.
- 전체 길이 약 3.6초는 기존 기획의 참고값이다. 준비와 복귀는 천천히, 중간 회전은 빠르게 읽히도록 포즈를 배분한다. 이번 작업에 클립·GIF/APNG·재생 타임라인은 포함하지 않는다.

## 포즈 목표

| 프레임 | 시계 방향 각도 | 역할 |
| --- | --- | --- |
| 00 | 0 | 고정 Idle 마스터 파일 그대로 |
| 01~03 | 6, 15, 30 | 팔을 조금 모으고 회전 시작, 천은 뒤늦게 반응 |
| 04~06 | 45, 60, 75 | 기울기 증가, 손목과 천 후행 |
| 07 | 90 | 머리 오른쪽, 몸통 수평, 얼굴 정면 유지 |
| 08~11 | 108, 126, 144, 162 | 거꾸로 향하며 천이 큰 곡선을 이룸 |
| 12 | 180 | 머리 아래, 거꾸로 된 정면 가면·흉갑 |
| 13~16 | 198, 216, 234, 252 | 반대쪽 수평 자세로 연결 |
| 17 | 270 | 머리 왼쪽, 몸통 수평, 얼굴 정면 유지 |
| 18~21 | 288, 306, 324, 342 | 세워지는 방향으로 감속 |
| 22~23 | 355, 360 | 손을 풀고 천의 관성을 정리, Idle 연결 |

각도는 생성 포즈의 목표값이며 픽셀에서 정밀 실측한 각도나 Unity Transform 설정값이 아니다. 07·12·17 최대 자세를 먼저 검토하고 연결 프레임을 제작한다. 23은 00 복제 대신 복귀 후 천의 잔여 흐름을 그린다.

## 출력과 검수

- 24개 고유 셀 00~23, 각 1024×1024 RGBA, Center (512,512), PPU 24. 현재 1024 마스터의 100% 체격을 유지하며 과거 72% 축소를 다시 적용하지 않는다.
- Part1: 00~15, 4×4·4096×4096. Part2: 16~23, 4×2·4096×2048. 왼쪽 위부터 행 우선 순서. 두 시트 경계 15→16은 연속 동작이며 중간 정지하지 않는다.
- 모든 alpha>0에 사방 최소 64px 여백. 연결된 천·발광을 잘라내거나 alpha 문턱 처리로 맞추지 않는다. 완전히 분리된 희미한 잡점 정리는 조건과 수량을 기록한다.
- 생성 요청 해상도와 실제 출력 해상도를 구분한다. 전체 정사각 캔버스의 공통 정규화만 허용하며 Trim·fit·자동 재중앙 정렬·개별 배율 보정을 하지 않는다.
- 개별 셀을 정수 좌표로 그대로 조립하고 시트 재추출 RGBA 일치를 확인한다. Unity Multiple 총 24개·이름·Rect·Center·PPU·실제 해상도를 검사한다.
- 원본·프롬프트·제외 후보·측정·정적 비교는 프로젝트 안에 보존한다. [제작 기록](../../../Docs/Boss/AirBoss/AirBoss_Cast_Spin360_v02.md)에 결과와 실제 검증 범위를 남긴다. 실제 재생·게임 크기·사용자 최종 아트 승인은 별도다.
