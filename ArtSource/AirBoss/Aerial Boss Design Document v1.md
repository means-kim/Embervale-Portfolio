## 1. 🎯 보스 개요와 전투 목표

### 1-1. 보스의 정체성

보스는 설산 배경과 어우러지는 거대한 공중 존재입니다. 기본 상태에서는 카메라 정면을 바라보며 떠 있고, 이동·시전·회전·대시 과정에서는 몸 전체가 크게 움직입니다.

흰 망토와 서리 천은 단순한 장식이 아니라 **보스의 움직임과 관성을 전달하는 핵심 요소**입니다. 몸통이 먼저 움직이고, 어깨와 팔, 망토의 부착부, 긴 천의 끝으로 움직임이 이어지도록 제작합니다.

보스는 손이나 몸을 직접 부딪쳐 피해를 주지 않습니다. **실제 공격은 별도로 생성되는 공격 오브젝트가 담당하며, VFX는 그 공격을 시각적으로 표현합니다.**

### 1-2. 핵심 전투 흐름

**보스의 전조 동작 → 빨간 위험 가이드 → 공격 발동 → VFX와 피해 판정 → 공격 종료 및 반격 기회**

플레이어는 보스의 자세를 통해 공격의 성격을 파악하고, 빨간 가이드를 통해 실제 위험 위치를 확인합니다.

보스의 동작이 끝나는 시점과 공격 오브젝트가 사라지는 시점은 반드시 같을 필요는 없습니다. 다만 지속 공격이 남아 있는 경우에도 **플레이어가 이동할 안전 공간과 반격할 기회**를 확보하도록 설계합니다.

### 1-3. 확정된 전투 방향

| 구분 | 기준 |
| --- | --- |
| 기본 시선 | Idle에서는 카메라 정면을 바라봅니다. |
| 이동 방식 | 공중에서 좌우로 이동하며, 이동 방향으로 몸을 기울입니다. |
| 공격 방식 | 보스 본체의 직접 타격 없이 VFX 기반 공격을 사용합니다. |
| 공격 예고 | 본체 전조와 빨간 위험 가이드를 함께 사용합니다. |
| 공격 계열 | 상단 낙하형, 지면 지정형, 다발형, 광역·지속형, 좌우 횡 이동형을 사용합니다. |
| 제외하는 공격 | 보스 손에서 전방으로 쏘는 독립적인 직선 발사·빔 패턴은 현재 범위에서 제외합니다. |
| 애니메이션 재사용 | 하나의 바디 애니메이션을 여러 공격 패턴에 연결할 수 있도록 설계합니다. |
| 좌우 재사용 | 이동과 90도 대시는 한 방향 제작 후 좌우 반전을 기본으로 합니다. |

**전방 직선형을 제외한다는 것은 모든 공격체의 직선 이동을 금지한다는 뜻은 아닙니다.** 다발형 공격체나 횡 이동형 공격의 이동 경로는 해당 패턴의 규칙에 따라 별도로 결정합니다.

## 2. 🎨 Visual Reference — 디자인 고정 기준

### 2-1. 기준 원화

**사용자가 이번 제작 기준으로 지정한 [1024×1024 정면 Idle 마스터](idle/AirBoss_Idle_Master_image2.png)를 유일한 체격·디자인 기준으로 사용합니다.** [v02 보존본](idle/AirBoss_Idle_Master_image2_v02.png)과 같은 이미지이며 현재 픽셀 크기를 100%로 사용합니다. 원본을 마스터로 만들 때 적용한 72% 축소를 다시 적용하지 않습니다.

다른 공격 이미지나 새로 생성한 자세는 동작 참고 자료로만 사용합니다. 다른 이미지의 얼굴 크기, 몸통 비율, 손 크기를 새로운 기준으로 혼용하지 않습니다.

노션 페이지에서는 이 항목에 최종 기준 원화를 함께 첨부하여 관리합니다.

### 2-2. 변경 금지 항목

| 항목 | 보존 기준 |
| --- | --- |
| 가면 | 형태, 길이, 크기, 주요 균열과 특징을 유지합니다. |
| 푸른 눈과 발광 | 눈의 위치와 기본 발광 구조를 유지합니다. |
| 목 주변 갑옷 | 높은 목 주변 갑옷의 형태와 연결 구조를 유지합니다. |
| 가슴과 몸통 | 가슴·몸통의 비율과 갑옷 배치를 유지합니다. |
| 양팔과 손 | 팔 길이, 손 크기, 신체에 연결되는 위치를 유지합니다. |
| 손가락과 발톱 | 개수, 기본 형태, 관절 구조를 유지합니다. |
| 망토·서리 천 | 몸에 붙는 위치와 주요 갈래의 연결 관계를 유지합니다. |
| 색상과 재질 | 전체 팔레트와 갑옷·천·서리의 재질감을 유지합니다. |
| 기본 방향 | Idle은 카메라 정면을 바라보는 자세를 유지합니다. |

### 2-3. 동작에 따라 허용하는 변화

관절 움직임, 몸통의 기울기, 동작에 따른 원근 변화, 천의 접힘과 휘어짐, 기존 부위가 가려지거나 다시 드러나는 변화는 허용합니다.

단, **동작 변화와 디자인 변경을 구분합니다.** 손을 정면으로 뻗어 원근상 크게 보이는 것은 허용하지만, 프레임마다 손의 기본 크기나 손가락 개수가 바뀌어서는 안 됩니다.

정면 기준은 기본 시선과 디자인 기준을 의미합니다. 승인된 회전·대시 동작까지 몸을 수직으로 고정하라는 의미는 아닙니다.

### 2-4. 주요 금지 사항

새로운 얼굴·갑옷·장식을 임의로 추가하지 않습니다. 망토의 주요 가닥을 편의상 없애거나 다른 위치에 붙이지 않습니다.

각 프레임을 셀에 맞추기 위해 개별 축소하거나, 폭과 높이를 서로 다르게 늘리지 않습니다. 자세 때문에 달라진 외곽 크기를 캐릭터의 체격 변화로 보정하지 않습니다.

## 3. 🎞️ 공통 애니메이션 제작 원칙

### 3-1. 전신이 움직이는 애니메이션

모든 동작은 팔이나 손만 움직이는 방식으로 끝내지 않습니다.

**몸통의 준비 → 어깨와 팔의 큰 움직임 → 손의 동작 → 망토와 서리 천의 후행 움직임 → 자세 회복**으로 연결합니다.

Idle과 Move에도 전신의 살아 있는 움직임을 넣되, 공격 전조와 혼동하지 않도록 실루엣과 리듬을 구분합니다.

### 3-2. 망토와 서리 천의 공통 규칙

| 상황 | 움직임 기준 |
| --- | --- |
| 동작 시작 | 몸통과 팔이 먼저 움직이고, 천은 조금 늦게 따라갑니다. |
| 이동 중 | 천이 이동 반대 방향으로 흐르며 속도감을 표현합니다. |
| 방향 전환 | 천의 끝은 이전 방향의 관성을 잠시 유지한 뒤 따라옵니다. |
| 강한 시전 | 천이 큰 곡선을 만들며 펼쳐지고, 본체보다 늦게 최대 움직임에 도달합니다. |
| 동작 정지 | 몸통이 먼저 안정되고, 천은 지나쳤다가 되돌아오는 움직임을 보입니다. |
| 루프 연결 | 마지막 프레임의 천 위치뿐 아니라 움직이던 방향도 첫 프레임과 자연스럽게 이어집니다. |

같은 천 가닥이 프레임마다 다른 곳에서 생겨나거나 사라져서는 안 됩니다. 단단한 갑옷과 고드름은 천처럼 늘어나지 않으며, 붙어 있는 부위를 따라 움직입니다.

### 3-3. 공통 동작 구조

공격과 주요 이벤트 모션은 다음 흐름을 기본으로 합니다.

**Ready → Anticipation → Hold → Main Motion / Cast → Follow Through → Recovery**

| 구간 | 목적 |
| --- | --- |
| Ready | 현재 Idle 또는 Move에서 새 동작으로 자연스럽게 진입합니다. |
| Anticipation | 몸 전체를 움직여 다음 행동을 예고합니다. |
| Hold | 전조의 핵심 자세를 잠시 유지하여 읽을 시간을 제공합니다. |
| Main Motion / Cast | 시전, 회전, 대시 등 해당 애니메이션의 핵심 행동을 수행합니다. |
| Follow Through | 팔과 몸통, 망토가 관성에 따라 계속 움직입니다. |
| Recovery | 자세를 회복하여 Idle 또는 Move로 연결합니다. |

Hold는 정해진 프레임을 무조건 오래 정지시키는 구간이 아닙니다. 필요하면 핵심 자세를 유지하면서 천의 작은 움직임을 이어갑니다.

### 3-4. 길이와 재생 속도

| 구분 | 적용 기준 |
| --- | --- |
| 공격·등장·회전·대시·사망 | 전체 행동 시퀀스는 **3초 이상**을 기본으로 합니다. |
| Idle | 현재 v02 **1.2초 루프**, 16장 각 0.075초. 기존 2.5~3초는 초기안입니다. |
| Move | **1.5~2.5초 루프**를 출발점으로 합니다. |
| 실제 대시 이동 | 전체 대시 시퀀스 중 짧고 빠른 구간에 집중합니다. |
| 실제 피해 시간 | 바디 애니메이션 길이와 별도로 정의합니다. |
| 지속형 시전 | 필요한 경우 유지 구간을 반복하거나 연장합니다. |

**전체 애니메이션이 3초 이상이라는 것은 실제 공격 판정이나 빠른 대시 이동까지 3초 이상 유지한다는 뜻이 아닙니다.**

전조와 회복에는 시간을 충분히 배분하고, 핵심 발동은 상대적으로 빠르게 표현합니다. 프레임 수와 클립 길이를 동일한 개념으로 취급하지 않습니다.

### 3-5. Idle·Move 재사용과 연결

Ready와 Recovery에서는 기존 Idle·Move 스프라이트를 적극적으로 참조합니다. 다만 큰 시전 자세에서 Idle을 갑자기 붙이는 방식은 사용하지 않습니다.

공격의 마지막 자세가 기본 자세로 가까워지도록 연결 프레임을 준비한 뒤, 공통 Idle 또는 Move로 복귀합니다.

**10종은 기본 동작의 분류입니다.** 실제 Unity Animation Clip은 필요에 따라 진입·반복·이탈 구간으로 나눌 수 있으며, 최종 파일 수가 반드시 10개일 필요는 없습니다.

## 5. 🧩 애니메이션별 상세 사양

아래 세부 동작과 시간 배분은 초기 제작안입니다. 각 동작의 Key Pose 검수 후 최종 타임라인으로 확정합니다.

### ANIM-01. `Idle_Float` — 기본 공중 부유

**목적:** 정면 기준 자세를 유지하면서 보스가 공중에 살아 있는 듯한 움직임을 표현합니다.

| 구간 | 바디 동작 |
| --- | --- |
| 0.0~1.0초 | 몸통이 완만하게 상승하는 흐름에 맞춰 가슴과 어깨가 열리고, 양팔이 조금 벌어집니다. |
| 1.0~2.0초 | 상승의 정점을 지나며 손목과 손가락이 자연스럽게 움직이고, 몸통이 천천히 하강 흐름으로 전환됩니다. |
| 2.0~3.0초 | 팔과 어깨가 기준 자세로 돌아오면서 다음 상승으로 이어집니다. |

**망토와 천:** 몸통의 상하 움직임보다 늦게 움직입니다. 좌우의 긴 가닥이 모두 같은 속도와 방향으로 움직이지 않도록 차이를 둡니다.

**연결:** 마지막에서 첫 프레임으로 넘어갈 때 몸통·손·천의 위치와 움직임이 자연스럽게 이어져야 합니다.

**공격 이벤트:** 사용하지 않습니다.

**주의:** 이미지 전체를 위아래로 이동시키는 것만으로 완성하지 않습니다. 실제 부유 이동을 코드로 처리한다면, 스프라이트 내부에 같은 상하 이동을 중복해서 넣지 않습니다.

**현재 제작 규칙:** v02의 짝수 00~14는 기존 8장을 그대로 보존하고 홀수 01~15는 각 구간의 새 중간 동작입니다. 00은 마스터 픽셀 그대로입니다. 캔버스 전체 이동·배율 변화는 넣지 않습니다. 각 0.075초씩 총 1.2초이며 15가 기존 07→00을 연결합니다. 위 0~3초 동작 표는 초기 동작 의도의 이력이고, 실제 타이밍은 [v02 기록](../../Docs/Boss/AirBoss/AirBoss_Idle_Float_v02.md)을 따릅니다.

### ANIM-02. `Encounter_Start` — 등장 및 전투 시작

**목적:** 전투 진입 시 보스의 존재감과 규모를 보여 줍니다.

| 구간 | 바디 동작 |
| --- | --- |
| 0.0~1.0초 | 전투 전 기본 자세에서 고개와 몸통을 숙이고, 팔을 몸 가까이 모으며 준비합니다. |
| 1.0~2.2초 | 몸통을 크게 일으키고 양팔을 넓게 펼치며 위세를 드러냅니다. |
| 2.2~3.6초 | 어깨와 팔의 관성을 정리하면서 정면 Idle 자세로 복귀합니다. |

**망토와 천:** 본체가 펼쳐진 뒤 천이 뒤늦게 크게 퍼집니다. 본체가 안정된 뒤에도 잔여 움직임이 이어집니다.

**연결:** `전투 전 Idle → Encounter_Start → Idle_Float`로 연결합니다.

**이벤트:** 연출용 VFX·사운드의 실행 지점을 둘 수 있습니다. 기본안에서는 이 연출 자체에 피해 판정을 넣지 않습니다.

**전투 시작:** 등장 연출이 끝나고 플레이어가 보스 상태를 읽을 수 있는 시점부터 패턴 선택을 시작합니다. 별도의 조작 잠금 여부는 미정입니다.

### ANIM-03. `Move_Bank` — 좌우 기울기 이동

**목적:** 공중 이동 방향과 관성을 전신으로 표현합니다.

**제작 방향:** 오른쪽 이동을 기준으로 제작하고, 왼쪽은 좌우 반전하여 재사용합니다.

| 구간 | 바디 동작 |
| --- | --- |
| 진입 | 현재 Idle에서 몸통·어깨·머리가 이동 방향으로 기울어집니다. |
| 이동 루프 | 기울어진 자세를 유지하면서 몸통과 팔에 완만한 움직임을 넣습니다. 루프 초기 길이는 2.0초입니다. |
| 이탈 | 이동을 감속하고 몸을 세웁니다. 팔과 천의 관성을 정리한 뒤 Idle로 복귀합니다. |

**망토와 천:** 이동 반대 방향으로 크게 흐릅니다. 정지할 때는 본체보다 늦게 따라오며 반대쪽으로 되돌아오는 움직임을 보입니다.

**연결:** `Idle → 이동 진입 → Move_Bank 반복 → 이동 이탈 → Idle`을 기본으로 합니다.

**공격 연결:** 일반 이동 자체에는 피해가 없습니다. 횡 이동형 패턴과 결합할 때만 별도 공격 오브젝트가 동작합니다.

**주의:** 이동 루프를 반복할 때마다 몸을 세웠다가 다시 기울이지 않습니다. 이동의 시작과 종료, 유지 루프를 구분합니다.

### ANIM-04. `Cast_OneArm_UpDown` — 한 팔 상승·하강 시전

단팔 동작에 사용할 팔은 Key Pose 검수 때 고정합니다. 이후 프레임마다 사용 팔이 바뀌지 않도록 캐릭터 기준과 화면 기준을 함께 기록합니다.

| 1.2~1.7초 | 들어 올린 팔과 손을 명확한 궤적으로 내리며 시전합니다. 몸통도 동작 방향으로 따라갑니다. |

**이벤트 후보:** 전조 중 위험 가이드 표시 요청, 팔을 내리는 핵심 시점에 공격 발동 요청을 배치합니다.

**연결:** Idle 또는 이동 종료 자세에서 진입하고, 회복 후 Idle·Move로 연결합니다.

**판정:** 손과 팔에는 직접 공격 판정을 넣지 않습니다.

| --- | --- |

**연결:** 기본 시퀀스는 3.6초이며, 지속 시전이 필요한 경우 중간 유지 구간을 별도 반복 구간으로 확장할 수 있습니다.

**다른 모션과의 구분:** 이 모션의 핵심은 **들어 올린 뒤 유지하는 것**입니다. 강하게 내리치는 동작은 `Cast_BothArms_LiftDrop`이 담당합니다.

## 6. ⚔️ 공격 패턴 구성과 애니메이션 매핑

### 6-1. 공격 계열

VFX 에셋은 아직 확정하지 않습니다. 아래 예시는 **공격 기능을 설명하기 위한 후보**이며 최종 리소스 선정 결과가 아닙니다.

| 패턴 ID | 공격 계열 | 주요 바디 애니메이션 | VFX 후보 | 기본 회피 목표 |
| --- | --- | --- | --- | --- |
| PAT-01 | 상단 낙하형 | `OneArm_UpDown`, `BothArms_Raise`, `ForwardReach` | 고드름, 번개, 낙하 얼음 | 예고된 낙하 위치에서 벗어납니다. |
| PAT-02 | 지면 지정형 | `BothArms_LiftDrop`, `ForwardReach` | 얼음 가시, 얼음 기둥, 지면 폭발 | 지정된 위험 영역을 이탈합니다. |
| PAT-03 | 다발형 | `BothArms_Raise` | 다수 얼음탄, 순차 낙하체 | 발사 순서와 빈 공간을 읽고 이동합니다. |
| PAT-04 | 광역·지속형 | `Spin360`, `BothArms_Raise`, `ForwardReach` | 눈보라, 냉기 필드, 광역 얼음 | 위험 영역 밖 또는 정해진 안전지대로 이동합니다. |
| PAT-05 | 좌우 횡 이동형 | `Dash_Side90`, `Move_Bank` | 이동하는 눈보라, 얼음 폭풍, 이동 장판 | 공격 경로와 진행 방향을 확인하여 피합니다. |

### 6-2. 패턴 재사용 원칙

바디 애니메이션에 특정 VFX 프리팹을 고정하지 않습니다.

예를 들어 `Cast_BothArms_Raise`는 다발형 공격체를 소환하는 데 사용할 수도 있고, 상단 낙하형 공격을 준비하는 데 사용할 수도 있습니다.

다만 같은 동작을 재사용하더라도 빨간 가이드의 위치·모양·진행 정보로 실제 위험을 구분할 수 있어야 합니다. 같은 신호 뒤에 회피 방법이 전혀 다른 공격을 예고 없이 발생시키지 않습니다.

### 6-3. 공격 패턴별 확정할 데이터

| 데이터 | 결정할 내용 |
| --- | --- |
| Pattern ID | 공격을 식별하는 고유 이름입니다. |
| Body Animation | 사용할 바디 애니메이션입니다. |
| Target Rule | 플레이어 위치, 고정 지점, 맵 구역 중 어디를 목표로 할지 정합니다. |
| Telegraph | 빨간 가이드의 모양, 범위, 표시 시간을 정합니다. |
| Spawn Rule | 상단, 지면, 좌우 경계, 보스 주변 중 생성 기준을 정합니다. |
| Release Timing | 바디 시전과 공격 발생을 연결할 시점입니다. |
| Damage Rule | 단발, 개별 공격체, 지속 피해 중 처리 방식을 정합니다. |
| Lifetime | 공격체와 위험 영역이 유지되는 시간입니다. |
| Recovery / Cooldown | 보스의 회복 시간과 해당 패턴의 재사용 간격입니다. |
| Cancel Rule | 시전 취소, 보스 사망, 전투 재시작 시 정리 방식을 정합니다. |

## 7. 🔴 빨간 위험 가이드 — Telegraph 규칙

### 7-1. 공통 원칙

**빨간 가이드는 “곧 위험해질 위치”를 알려주며, 가이드 자체에는 피해가 없습니다.**

실제 위험이 시작되기 전에 위치와 범위를 확인할 시간을 제공합니다. 공격 발동 직전 가이드를 다른 위치로 순간 이동시키거나, 예고 없이 범위를 확대하지 않습니다.

색상은 빨간색으로 통일하되, 모양·테두리·진행 방향·채워지는 표현을 함께 사용합니다. 빨간색만으로 모든 정보를 전달하지 않습니다.

### 7-2. 공격별 표시 방식

| 공격 계열 | 가이드 표현 기준 |
| --- | --- |
| 상단 낙하형 | 낙하 지점과 폭을 표시합니다. 공중에서도 맞을 수 있는 공격이라면 세로 위험 구간도 읽히도록 표현합니다. |
| 지면 지정형 | 지면의 공격 폭과 범위를 표시합니다. 높이까지 위험한 공격이면 그 높이도 구분할 수 있어야 합니다. |
| 다발형 | 생성 위치, 초기 진행 방향, 발사 순서 또는 착탄 위치 중 회피에 필요한 정보를 표시합니다. |
| 광역·지속형 | 위험 영역의 경계를 명확하게 표시하고, 안전 공간과 구분합니다. |
| 좌우 횡 이동형 | 공격이 지나는 높이·두께·진행 방향을 긴 띠와 방향 표시 등으로 예고합니다. |

### 7-3. 목표 위치 고정 — 초기 구현안

위치 지정형 공격은 **가이드가 나타날 때 목표 위치를 기록하고 고정하는 방식**을 기본 테스트안으로 사용합니다.

플레이어를 따라가는 추적 가이드가 필요하다면, 추적 구간과 위치 고정 시점을 별도로 정의합니다. 공격 직전까지 추적하다가 즉시 피해를 주는 방식은 기본안에 포함하지 않습니다.

위험 영역이 새로 생기거나 진행 방향이 바뀌면, 해당 변화에도 별도의 예고를 제공합니다.

### 7-4. 가이드와 실제 판정의 일치

실제 피해 영역은 예고한 영역을 벗어나지 않도록 맞춥니다. VFX의 장식용 빛·안개·작은 파편이 실제 판정보다 넓게 보이는 경우에는 위험의 중심과 경계가 구분되도록 표현합니다.

시전 준비용 빛이나 에너지 연출은 가이드 이전에도 사용할 수 있습니다. 하지만 이러한 준비 VFX에는 피해를 주지 않습니다.

### 7-5. 타이밍 예시 — 지면 지정형 초기안

| 시점 | 보스 동작 | 공격 상태 |
| --- | --- | --- |
| 0.0~0.6초 | 양팔 상승 전조를 시작합니다. | 피해가 없습니다. |
| 0.6초 | 전조가 진행됩니다. | 목표를 고정하고 빨간 가이드를 표시합니다. |
| 0.6~1.5초 | 최대 전조와 하강 준비를 보여 줍니다. | 약 0.9초의 위치 이탈 시간을 제공합니다. |
| 1.5초 전후 | 양팔이 강하게 내려옵니다. | 공격을 발동하고, 실제 위험 표현에 맞춰 피해 판정을 시작합니다. |
| 이후~3.4초 | 후행 동작과 자세 회복을 진행합니다. | 패턴에서 정한 시점에 피해를 종료하고 공격을 정리합니다. |

위 수치는 **프로토타입용 초기안**입니다. 최종 가이드 시간은 플레이어 이동 속도, 공격 폭, 카메라 범위, 실제 회피 수단에 맞춰 조정합니다.

## 8. ✨ VFX와 피해 판정 분리

### 8-1. 역할 구분

| 구성 요소 | 담당 역할 |
| --- | --- |
| 보스 Body | 전조, 시전, 이동, 회복, 사망을 표현합니다. |
| Telegraph | 공격 위치와 위험 범위를 예고합니다. |
| 공격 VFX | 낙하·폭발·눈보라 등 공격의 시각적 모습을 표현합니다. |
| 공격 판정 로직 | 실제 충돌·영역 검사, 피해량, 지속 피해 간격을 관리합니다. |
| 보스 피격 영역 | 플레이어가 보스에게 피해를 줄 수 있는 영역을 관리합니다. |

**VFX가 보인다는 사실만으로 자동으로 피해가 발생하는 구조로 생각하지 않습니다.** 공격 오브젝트 안에서 시각 효과와 판정 로직을 구분하고, 실제 위험 표현과 피해 활성 시간을 맞춥니다.

### 8-2. VFX 생성 위치

| 생성 기준 | 사용 예시 |
| --- | --- |
| 맵 상단 | 지정 X좌표 위에서 고드름이나 낙하체를 생성합니다. |
| 지면의 지정 위치 | 얼음 가시, 기둥, 폭발을 생성합니다. |
| 맵의 특정 영역 | 눈보라나 지속 필드를 생성합니다. |
| 맵 좌우 경계 | 횡 이동형 공격을 시작합니다. |
| 보스 중심 | 보스 주변의 광역 연출이나 소환 배치를 구성합니다. |
| 보스 손·가슴 | 필요할 경우 준비 에너지나 소환 연출의 기준점으로 사용합니다. |

보스가 화면 정면으로 손을 뻗더라도 공격은 맵 상단이나 플레이어 주변에서 발생할 수 있습니다. 손의 위치와 공격 생성 위치를 항상 같게 만들 필요는 없습니다.

### 8-3. 피해 처리 규칙 — 초기 구현안

단발 공격은 같은 공격에 중복 접촉하여 의도치 않게 여러 번 피해를 받지 않도록 관리합니다.

지속형 공격은 대상별 피해 간격을 별도로 관리합니다. 여러 시각 파티클이 겹쳤다는 이유로 매번 추가 피해를 주지 않습니다.

| 상황 | 기본 처리안 |
| --- | --- |
| 전조 중 | 피해 판정을 비활성화합니다. |
| 공격 발동 | 실제 위험이 시작되는 표현에 맞춰 판정을 활성화합니다. |
| 바디가 Recovery로 진입 | 이미 발동한 공격은 패턴에서 정한 수명 규칙을 따릅니다. |
| 발동 전 시전 취소 | 남은 가이드와 예약된 공격을 취소합니다. |
| 보스 사망 | 신규 공격과 피해 판정을 중단하고, 진행 중인 위험 요소를 정리합니다. |
| 전투 재시작 | 이전 전투의 가이드·공격체·예약 실행을 모두 초기화합니다. |

보스가 Idle로 돌아왔다는 이유만으로 모든 공격체를 즉시 삭제하지 않습니다. 반대로 지속 공격을 제한 없이 남겨 다음 공격과 누적시키지도 않습니다.

## 9. 🔄 좌우 방향과 Flip 처리

### 9-1. 제작 기준

`Move_Bank`와 `Dash_Side90`는 오른쪽 방향을 기준으로 제작하고 왼쪽은 반전하여 재사용합니다.

이 반전은 제작량 절감을 위한 승인된 사용 방식입니다. 좌우 버전을 별도로 생성하면서 가면·갑옷·천의 디자인이 달라지는 방식은 피합니다.

### 9-2. 구현 시 확인 사항

Unity의 `SpriteRenderer.flipX`는 스프라이트 렌더링을 반전하지만, 콜라이더 등 다른 컴포넌트까지 반전하지는 않습니다. 따라서 손 소켓, 비대칭 피격 영역, 공격 생성 오프셋이 필요하면 방향에 맞춰 별도로 처리합니다. Unity 문서

**보스 이동 방향, 그림의 반전 상태, 공격의 진행 방향은 각각 구분하여 관리합니다.**

보스가 오른쪽으로 이동하면서 맵 상단의 고정 위치를 공격할 수도 있으므로, 모든 공격 방향을 Body의 Flip 상태만으로 결정하지 않습니다.

### 9-3. Idle 복귀 검수

기준 원화의 망토 배치는 좌우가 완전히 같지 않을 수 있으므로, 반전된 Move·Dash에서 비반전 Idle로 돌아올 때 천의 배치가 갑자기 바뀌지 않는지 확인합니다.

필요하면 방향별 종료 자세나 연결 프레임을 준비합니다. 반전 상태를 바꾸는 것만으로 연결이 자연스러워졌다고 판단하지 않습니다.

## 10. 🛠️ 애니메이션과 패턴 로직 연결

### 10-1. 책임 분리

바디 애니메이션은 동작의 핵심 시점을 알리고, 패턴 로직은 현재 선택된 공격 데이터에 따라 가이드와 공격 오브젝트를 생성합니다.

Unity의 Animation Event는 애니메이션 재생 중 지정한 시점에 스크립트 함수를 호출할 수 있으므로, 이러한 시전 신호를 전달하는 방법으로 사용할 수 있습니다. Unity Documentation

### 10-2. 이벤트 역할 — 초기 명칭안

| 이벤트 역할 | 처리 내용 |
| --- | --- |
| `WarningCue` | 현재 패턴의 위험 가이드 표시를 요청합니다. |
| `CastCue` | 현재 패턴의 공격 발동을 요청합니다. |
| `RecoveryCue` | 바디가 회복 구간에 들어갔음을 알립니다. |
| `ActionFinished` | 현재 행동의 종료와 다음 상태 전환을 요청합니다. |
| `DeathFinished` | 사망 연출 종료와 전투 종료 처리를 요청합니다. |

이 이름은 역할을 설명하기 위한 초기안입니다. 실제 스크립트와 함수 이름은 구현 시 통일합니다.

### 10-3. 안전 규칙

이벤트를 받았을 때 현재 보스 상태와 진행 중인 패턴이 유효한지 확인합니다. 취소되거나 사망한 뒤 도착한 발동 요청으로 새 공격이 생성되지 않도록 합니다.

반복 클립과 반복 피해는 구분합니다. 채널링 자세가 반복되더라도 공격 생성 횟수와 피해 간격은 패턴 규칙으로 제어합니다.

가이드 시간, 공격 발동, 실제 피해 시작은 하나의 패턴 타임라인을 기준으로 맞춥니다. 바디 재생 속도만 바꾸고 가이드나 피해 타이밍을 그대로 두지 않습니다.

## 11. 📐 멀티스프라이트 제작 규격

### 11-1. 현재 확정된 제작 원칙

**현재 마스터와 Idle의 1차 픽셀 규격은 아래와 같이 적용합니다.** 다른 동작도 같은 체격·좌표계를 출발점으로 하되 최대 포즈의 적합성은 별도 확인합니다. 기존 설산 거인의 셀·접지선·피벗 값을 그대로 적용하지 않습니다. 상세 규칙은 [멀티스프라이트 제작 규칙](AirBoss_Multisprite_Production_Rules_v1.md)이 기준입니다.

| 항목 | 상태와 기준 |
| --- | --- |
| 출력 형식 | RGBA 투명 PNG를 사용합니다. |
| 애니메이션 방식 | 전신 스프라이트 교체 방식으로 제작합니다. |
| 공통 배율 | 현재 1024 Idle 마스터의 픽셀 크기 100%와 얼굴·몸통·팔 비율을 유지합니다. |
| 셀 크기 | 마스터·Idle은 1024×1024. 다른 동작의 최대 포즈 적합성은 미검증입니다. |
| 프레임 수 | Idle v02는 16장. Move 16장, 일반 캐스팅 12장, 핵심 공격·회전·사망 16장은 후속 목표입니다. |
| 시트 배열·전체 해상도 | Idle v02는 4열×4행, 4096×4096. 다른 동작은 Key Pose 검토 후 정합니다. |
| 피벗 | 셀별 Center, (512,512), 정규화 (0.5,0.5)를 제작·임포트 기준으로 합니다. |
| PPU | **24**. 2026-09-30 사용자 확정. Idle 및 후속 AirBoss 스프라이트에 공통 적용하며 PNG 규격·마스터 배율은 유지합니다. |
| 안전 여백 | 모든 셀 사방 64px의 완전 투명 띠를 검사합니다. 현재 마스터의 모든 alpha>0 픽셀 기준 최소 여백은 84px입니다. |
| VFX 포함 여부 | 공격용 대형 VFX와 빨간 가이드는 Body 시트에서 분리합니다. |

Idle 8장은 1차 산출 규격이며 3초 재생의 부드러움까지 검증된 장수는 아닙니다. 부족한 동작을 복제 프레임으로 채우지 않고, 추가 연결 그림이 필요하면 장수·배열·시트 규격을 함께 갱신합니다. Idle 이외의 장수는 후속 제작 목표입니다.

### 11-2. 좌표와 정렬

공통 캔버스 좌표계에서 가면·가슴·몸통의 기준 위치를 기록합니다. **피벗 위치와 그림 안의 가슴 위치는 별개의 값으로 관리합니다.**

천이 한쪽으로 길게 펼쳐졌다는 이유로 프레임 전체를 외곽 중앙에 다시 맞추지 않습니다. 팔을 높이 들었다는 이유로 해당 프레임만 축소하지 않습니다.

의도적인 몸통 기울기와 움직임은 유지하되, 자동 재정렬 때문에 생기는 불필요한 위치 이동을 방지합니다.

### 11-3. 최대 동작 범위 검수

최소한 다음 자세가 같은 기준 배율로 들어가는지 확인합니다.

**양팔 최고 상승 자세, 양팔 최대 확장 자세, 360도 회전 중 최대 외곽, 90도 대시 자세, 사망 시 최대 기울기**를 비교합니다.

공간이 부족하면 동작 범위나 공통 제작 규격을 재검토합니다. 특정 동작만 잘라내거나 줄여서 해결하지 않습니다.

### 11-4. 제작 순서

**v01 제작 당시 단계 (현재 v02는 16장·클립 연결 완료):** 1024 마스터 기반 Idle v01 8장·4×2 시트·Unity Multiple 분할까지 제작했으며 전체 정적 검토 대기입니다. 애니메이션 클립·실제 루프·게임 크기 검증은 미진행입니다.

Idle은 **마스터 확인 → 00·02·04·06 주요 상태 → 01·03·05·07 연결 → 전신·여백·루프 검수 → 시트 조립 → 실제 파일 검수 → 별도 Unity 테스트** 순서로 진행합니다.

다른 동작을 양산하기 전에는 **같은 체격의 주요 자세 설계 → 최대 동작 범위 확인 → 공통 규격 적합성 검토 → 연결 프레임 제작**을 거칩니다. Idle을 먼저 만들었다는 이유로 모든 최대 동작이 검증된 것으로 취급하지 않습니다.

시트 완성 후에는 파일명이나 미리보기만 보지 않고 실제 해상도, 투명도, 셀 배치, 잘림 여부를 확인합니다.

## 12. 🎮 보스 피격과 실제 플레이 검증

### 12-1. 보스의 공격 판정과 피격 판정 구분

보스 본체가 직접 피해를 주지 않는 것과, 플레이어가 보스를 공격할 수 있는지는 별개의 문제입니다.

**플레이어가 어떤 위치를 공격하여 보스에게 피해를 줄 수 있는지**는 반드시 별도로 확정합니다. 망토 끝까지 자동으로 보스의 피격 영역으로 삼지 않습니다.

### 12-2. 프로토타입에서 먼저 확인할 사항

| 확인 항목 | 검증 내용 |
| --- | --- |
| 보스 크기 | 실제 카메라에서 가면·손·전조가 구분되는지 확인합니다. |
| 부유 높이 | 플레이어가 의도한 방식으로 공격할 수 있는지 확인합니다. |
| 피격 영역 | 보이는 본체와 맞는 영역이 납득되는지 확인합니다. |
| 반격 기회 | 공격 회피 후 실제로 반격할 시간과 공간이 있는지 확인합니다. |
| 이동 범위 | 보스가 화면 밖으로 빠지거나 위험 가이드를 가리지 않는지 확인합니다. |
| 회피 수단 | 플레이어의 실제 이동·점프·대시 구현으로 피할 수 있는지 확인합니다. |

대시의 무적 여부나 공중 공격 가능 범위는 이 문서에서 임의로 확정하지 않습니다. 플레이어의 실제 구현과 맞춰 검증합니다.
