# 양손 모으기 · 번개 응축 v02

2026-10-04 최신 사용자 피드백: 팔 동작은 자연스럽지만 천과 전체 반응이 정지되어 밋밋하다. 천·몸통의 움직임을 보완하고 그림이 들어오면 셀을 1024×1024로 바꾼다. 24프레임과 클립 미생성 조건은 유지한다.

## 변경한 움직임

- 01~06: 가슴·어깨가 조금 펴지며 준비하고, 왼쪽 위 천 고리와 오른쪽 아래 긴 천이 바깥으로 부푼다. 팔이 모이기 시작해도 천의 바깥 흐름은 잠시 이어진다.
- 07~13: 몸통과 고개가 손 쪽으로 조금 숙여지고 천의 주름·끝이 뒤늦게 안으로 감긴다.
- 14~17: 손 모으기 유지 중 천이 조금 풀리고 잔흔들림이 이어진다.
- 18~22: 손을 풀면서 천이 바깥으로 되돌아갔다가 가라앉는다.
- 00과 23: [1024 Idle 원본](../idle/AirBoss_Idle_Master_image2.png) 그대로, RGBA 바이트 일치.

v01의 프레임별 팔·손·번개 포즈를 참조해 built-in image_gen으로 01~22를 편집했다. 단순 전신 이동·회전·크기 변경이나 반투명 중첩으로 천의 움직임을 대신하지 않았다. 천의 말림 연결과 17의 너무 이른 손 풀기를 발견해 07/13/14/15/17을 추가 수정했다. 생성 편집이므로 팔·손·갑옷의 미세한 묘사까지 v01과 동일 픽셀은 아니다.

## 1024 셀과 크기

| 항목 | v02 실제 값 |
| --- | --- |
| 요청 / 생성 출력 | 1024×1024 / 1254×1254 RGBA |
| 개별 셀 | 1024×1024 RGBA, 24장 |
| Part1 | 00~15 · 4×4 · 4096×4096 |
| Part2 | 16~23 · 4×2 · 4096×2048 |
| Unity | Sprite Multiple · PPU 24 · Center (512,512) · Max Size 4096 |

생성 출력의 전체 정사각 캔버스를 1024로 동일 규격화했다. v01에서 추가했던 사방 64px 패딩은 v02에 넣지 않았다. 프레임별 외곽 크기에 맞춘 fit·Trim·재중앙정렬은 없다. 원본 기준점과 PPU가 같아 **셀 여백 변경 자체로 몸체 표시 배율은 변하지 않는다.** 천을 새로 그리면서 달라진 외곽과 숙임은 동작의 변화이며 크기를 보정한 결과가 아니다.

v01의 1152 셀 내부 1024를 검사한 결과, 바깥 64px의 비투명 픽셀은 alpha=1/255의 거의 보이지 않는 생성 잔점이었다. v02도 같은 성질의 잔점이 일부 남는다. 이를 임의로 지우거나 alpha를 다시 만들지 않고 보존하면서 최신 사용자의 1024 셀 요구를 반영했다. **모든 alpha>0 픽셀에 대한 사방 64px 완전 투명 검사를 통과했다고 표시하지 않는다.** 실제 그림의 alpha>2 경계는 전 프레임 (64,64)~(960,960) 안에 있고, 바깥 64px의 최대 alpha는 1이다. [상세 검사](alpha_border_v02.json). 전체 1024 캔버스를 보존하므로 그림을 자르거나 천을 축소해서 맞춘 것은 아니다.
