## 새 소재

Assets/04.Sprites/Backgrounds/ClimbMap에 PNG+.meta 저장. 세 파일 모두 요청/실제1024×1536 RGBA, PPU100, Sprite Single, 중앙pivot, FullRect, Max2048, 무압축, Clamp, mipmap/Trilinear. 기존 원본은 보존했다.

|파일|역할|HTML X,Y|너비|
|---|---|---|---:|
|BG_Climb_EntryWall_v01.png|왼쪽 입구 위 벽. 하단은 투명|−450,0|1000|
|BG_Climb_ExitUpper_v01.png|오른쪽 출구 위 벽. 나머지 투명|450,−130|1000|
|BG_Climb_ExitLower_v01.png|오른쪽 출구 아래 벽. 상단 투명|450,70|1000|

밝기0.8 비교값. 각각 원본1024×1536 캔버스를 유지하며 투명 여백이 크다. 투명 여백을 자동으로 잘라내면 아래 배치 기준이 달라진다. 생성 결과는 정밀 픽셀 절단과 다르다. 입구 벽의 alpha128 이상 마지막 행은4픽셀 간격 샘플에서1350으로, 요청한86%보다 조금 길다. 실제 형태를 보고 배치했다.

## 바뀐 점

기존 왼쪽14%·오른쪽84%/23% CSS 잘라내기를 모두 제거했다. 새 PNG 자체의 알파로 통로가 열린다. 출구 위 벽은 새 돌출 끝을 고려해Y−130, 아래 벽은 발판 위로 튀어나온 부분을 피하도록Y70으로 옮겼다. 기존 발판9개의 소재·위치·크기는 유지했고 편집 UI도 유지했다. 큰 기둥 이음과 눈 끝을 재도입하지 않았다. 승인된 연결 바닥만 쓰는 시작맵 구도를 유지했다.

## Unity 배치

기존 좌벽 대신EntryWall, 우벽 대신ExitUpper와ExitLower를 별도 SpriteRenderer로 배치한다. 세 벽 자체에는 SpriteMask가 필요 없다. 원본 전체 프레임 중앙pivot이므로 보이는 조각 중심으로 좌표를 해석하지 않는다. 벽은 발판과 캐릭터보다 뒤에 표시한다. 통로 폭을 바꾸려면 위·아래 벽을 각각 이동한다. 장식 벽에 자동 콜라이더를 붙이지 않는다.

예시: HTML100단위=1월드단위, HTML(0,0)=Unity(0,0), Y방향 반전, 중앙pivot일 때 Scale=1000/1024=0.9765625. 세 중심위치는 각각 (0.5,−7.5), (9.5,−6.2), (9.5,−8.2). 이 값은 조립 비율 예시이며 최종 월드 크기나 카메라/캐릭터 설정을 확정하지 않는다. 모든 부모와 회전이 기본인 경우의 계산이다.

## 확인과 남은 범위

브라우저에서 입구·출구·전체 배치 및 시작맵 접합을 시각 확인. 이미지 로드 실패0. 표시된 벽6개(전체도+카메라)의 computed clip-path가 모두none임을 확인했다. 실내 하늘 없음,16:9·캐릭터 약9% 유지. 정지 화면에서 통로 공간을 확인했지만 실제 점프·걷기·충돌·패럴랙스는 미검증이다.

등반 벽 잘라내기는 해결했지만, 승인된 시작맵 연결의 v02 방식 배경 마스크와 전체 컨테이너 크롭은 남아 있다. 이번 작업을 전체 프로젝트의 모든 마스크 제거라고 부르지 않는다. Unity 씬·코드·프로젝트 전역 설정은 변경하지 않았다. 다음 판단은 사용자 실제 발판 배치와 이동 검증 후 진행한다.
