## Unity에서 조립

1. 기존 입구·등반 영역 위치와 캐릭터 크기를 먼저 맞춘다. 카메라16:9와 보이는 캐릭터 약9%는 아트 참고다.
2. 실내 후면은 입구 뒤까지 연장한다. v03은 실내 후면 컨테이너X1050, 폭1200, 높이1600이다. 배경 종횡비를 찌그러뜨리지 않고 cover 크롭한 시안이므로 실제 Unity에서는 충분히 큰 뒤벽과 앞쪽 암벽 가림으로 구성한다.
3. 입구 PNG의 오른쪽을 예전 배치도 경계에서 자르지 않는다. 시작맵 컨테이너는 폭1450까지 확장했다.
4. 아래 표의 암벽 두 조각을 입구·후면보다 앞, 캐릭터보다 뒤에 놓는다. 암벽 하단 조각은 뒤벽 역할이다. 길을 막는 충돌체를 추가하지 않는다.
5. 기존 바닥의 발 디딤 표면을 맞춘 뒤 연결 바위를 위에 겹친다. 이번 시안은 등반 입구 바닥을 기존보다15 HTML단위 내렸다. 그림의 투명 여백이나 이미지 하단으로 높이를 맞추지 않는다.
6. 눈 끝은 연결 바위보다 앞에 별도 배치한다. 본체와 합치지 않는다.
7. 지형에 밀착한 이음과 눈은 같은 이동·패럴랙스 기준을 공유한다. 카메라를 경계 좌우로 움직여 빈틈·빛 줄·캐릭터 가림을 확인한다.

권장 상대 정렬(기존 Sorting Layer 안에서 관계만 적용): 후면 < 입구/벽 < 암벽 이음 < 바닥 이음 < 눈 끝 < 캐릭터. 실제 프로젝트의 기존 정렬값을 존중한다. 새 전역 레이어나 설정을 이 작업에서 생성하지 않았다.

## 조립 수치

HTML 좌상단 좌표. 모든 PNG는 종횡비 유지. 밝기는 CSS 비교값이며 Unity 머티리얼/조명/색 공간에 따라 직접 일치하지 않을 수 있다.

|인스턴스|X|Y|너비|밝기|
|---|---:|---:|---:|---:|
|암벽 상부|1220|800|420|0.60|
|암벽 하부|1350|1170|220|0.35|
|연결 바닥|1110|1396|490|0.80|
|눈 끝|1100|1391|340|0.60|

계산 예시만: HTML(1250,1500)을 Unity(0,0), HTML100단위를1월드단위로 가정할 경우 다음과 같다. 최종 월드 크기 확정값이 아니며 기존 씬 크기에 맞게 전체를 동일 비율로 조정한다.

|인스턴스|중앙 pivot 위치 X,Y|균일 Scale|
|---|---|---:|
|암벽 상부|1.800,3.850|0.410156|
|암벽 하부|2.100,1.650|0.214844|
|연결 바닥|1.050,-0.185|0.276212|
|눈 끝|0.200,0.240|0.191657|

변환식: k=월드단위/HTML단위, h=너비×원본높이/원본너비. 중심X=(X+너비/2-1250)×k; 중심Y=(1500-Y-h/2)×k; 균일Scale=너비×k×PPU/원본너비. 카메라·캐릭터 값은 이 수치 때문에 임의 변경하지 않는다.

## 검토 결과와 한계

접합 확대와 전체도 실제 확인. 이미지 로드 실패0, 연결부 gradient mask0. 신규 PNG들은 RGBA와 모서리 알파0 확인. 입구 경계를 독립 암벽의 불규칙한 윤곽으로 덮었고 캐릭터는 그 앞에 표시된다. v02보다 암벽 돌출이 커진 구도이며 최종 사용자 확인 전이다. 바닥의 바위 크기 차이는 완전히 없어지는 것이 아니라 연결 조각을 거쳐 바뀐다.

새 이음 소재 자체에는 Sprite Mask/커스텀 셰이더가 필요하지 않다. 그러나 기존 전체 프로토타입의 등반 입출구 clip-path와 컨테이너 크롭은 남아 있다. 전체 맵을 PNG 단순 배치만으로 동일 재현했다고 주장하지 않는다. 해당 벽의 최종 분할/조립은 별도 과제다. Unity 씬·게임 코드·콜라이더·플레이·패럴랙스·눈 제거는 수정하거나 검증하지 않았다.

## 이후 이음 제작 기준

완성된 사각형 끝끼리 연결하지 않고, 겹침 영역과 불규칙한 끝 조각을 함께 준비한다. 바닥 표면·바위 크기·빛 방향을 먼저 맞춘다. 이음 조각을 과도하게 늘려서 덮지 않는다. 눈/암벽/충돌 분리는 유지한다. 실제 카메라에서 양옆·가운데를 확인하고 다음 구역으로 진행한다.
