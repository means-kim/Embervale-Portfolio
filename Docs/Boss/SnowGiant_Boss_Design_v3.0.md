# 2. ⚔️ 전투 목표

단순히 공격 속도가 빠른 전투보다 **크고 무거운 동작을 관찰하고 회피하는 전투**를 목표로 한다. 플레이어가 자세와 실루엣만 보고 다음 공격을 판단할 수 있도록 주요 공격마다 명확하고 서로 다른 전조를 제공한다.

- 공격이 갑자기 발생하지 않는다.
- 보스의 자세와 실루엣으로 다음 공격을 예측할 수 있다.
- 대시를 통한 회피를 적극적으로 사용한다.
- 회피 후 명확한 반격 기회를 제공한다.
- 거대한 체구에 어울리는 묵직한 움직임을 표현한다.
- 각 공격의 전조 자세가 명확하게 구분된다.
- Phase 2는 시각적 변화와 패턴 강화를 함께 제공한다.

# 3. ⭐ 애니메이션 핵심 제작 원칙

> **공격 부위만 움직이지 않는다. 모든 공격은 체중 이동과 전신 회전을 포함한다.**

팔 공격도 팔만 움직이지 않는다. **발 → 다리 → 골반 → 허리 → 몸통 → 어깨 → 팔 → 손**으로 힘이 전달되는 모습을 표현한다.

## ① Anticipation

공격 직전 실루엣 자체가 달라질 정도로 크게 준비한다. Swing은 팔을 조금 뒤로 옮기는 것이 아니라 몸 뒤쪽까지 크게 당기고, 몸통을 반대쪽으로 비틀며 골반을 회전하고 무릎을 굽힌다. 이 자세만으로 다음 공격을 판단할 수 있어야 한다.

## ② Weight Shift

예를 들어 오른팔 Swing 준비는 **뒷다리로 체중 이동 → 무릎 굽힘 → 골반을 반대 방향으로 회전 → 허리·몸통 비틀기 → 어깨·팔을 뒤로 당기기**다. 타격 순간에는 뒷다리에서 골반, 허리, 몸통, 어깨, 팔, 손으로 힘이 전달된다.

## ③ Follow Through

타격 순간 동작을 멈추지 않는다. **팔이 목표 지점을 지나침 → 몸통도 공격 방향으로 회전 → 앞다리에 체중 이동 → 몸이 잠시 무너짐 → 중심 회복 → Idle 복귀**로 관성을 표현한다.

## 프레임 규격

| 애니메이션 | 고유 스프라이트 |
| --- | ---: |
| Idle | 8 |
| Walk | 8 |
| Slam | 16 |
| Swing | 16 |

| Ice Spike / 얼음가시 전용 Body | 16 |
| Ground Smash | 16 |

**Idle·Walk를 제외한 주요 보스 Body 애니메이션은 기본 16프레임이다.** 얼음가시도 독립 공격이므로 이 규칙에 포함한다. 기존 별도 VFX 프리팹의 프레임 수를 Body와 강제로 같게 만드는 규칙은 아니다.

## 멀티스프라이트 이미지 규격

| 항목 | 규격 |
| --- | --- |
| 프레임 셀 | **512 × 512 px** |
| 8프레임 시트 | **2048 × 1024 px / 4열 × 2행** |
| 16프레임 시트 | **4096 × 1024 px / 8열 × 2행** |
| 배경 | RGBA 투명 |
| 정렬 참조 | **현재 Boss_Idle.png / Boss_Walk.png와 각각의 .meta** |
| Unity Pivot | **Bottom Center `(0.5, 0)`**, Idle·Walk와 동일 |
| 피봇 픽셀 좌표 | **`(256, 0)`**, 셀 좌하단 원점 기준 |
| 셀 기하학적 중심 | `(256, 256)` — 셀 자체의 중심이며 피봇·몸 중심과 구분 |
| PPU | **50**, Idle·Walk와 동일 |
| Slice Offset / Padding | **`(0,0) / (0,0)`**, 기존 균등 셀 배치와 동일 |
| 그림 배치 기준 | Idle·Walk의 셀 좌표계, 기준 자세의 몸 위치·크기, 접지선 유지 |
| 프레임별 보정 오프셋 | 그림을 자동 재중앙 정렬하거나 개별 Pivot/Transform으로 보정하지 않음 |
| 자동 Trim | 사용하지 않음 |

> **Center Pivot `(0.5,0.5)`로 변경하지 않는다.** 셀 중심 `(256,256)`은 기하학적 정보이며 캐릭터를 그 점에 매 프레임 맞추라는 뜻이 아니다.

프레임 순서는 **위 행 왼쪽 → 오른쪽 → 아래 행 왼쪽 → 오른쪽**이다.

```text
8프레임 / 2048 × 1024 / 각 셀 512 × 512
[01][02][03][04]
[05][06][07][08]

16프레임 / 4096 × 1024 / 각 셀 512 × 512
[01][02][03][04][05][06][07][08]
[09][10][11][12][13][14][15][16]
```

# 5. ⏱ 공격 애니메이션 시간 규격

공격 클립 1개의 기본 길이는 **약 3초**다. 고유 스프라이트 16장을 같은 시간 간격으로 재생하지 않고 구간마다 유지 시간을 다르게 설정한다.

| 구간 | 시간 | 사용 스프라이트 | 역할 |
| --- | --- | --- | --- |
| Ready | 0.00~0.25초 | 기존 Idle 재사용 | 공격 직전 기본 자세 |
| Anticipation / Weight Shift | 0.25~1.15초 | 공격 01~06 | 전조·힘 모으기 |
| Attack | 1.15~1.50초 | 공격 07~10 | 빠른 공격·타격 |
| Follow Through | 1.50~2.30초 | 공격 11~16 | 공격 관성 |
| Recovery | 2.30~3.00초 | 기존 Idle 재사용 | 기본 자세 복귀 |

**공격 고유 스프라이트는 16장 모두 별도 동작으로 제작한다.** Ready·Recovery의 Idle은 이 16장에 포함하지 않는다. 16프레임 시트의 첫·마지막 칸을 Idle 복사본으로 채워 고유 공격 프레임을 줄이지 않는다.

`Idle → Attack 01~16 → Idle`로 클립에서 서로 다른 시트의 Sprite를 참조한다. 첫 공격 프레임과 마지막 Follow Through 자세는 Idle과 자연스럽게 이어지도록 만든다. 기존 Idle의 셀 정렬과 피봇을 공유해 교체 시 전체 이미지가 튀지 않게 한다.

약 3초와 위 타임라인은 **공격 클립의 기준**이다. Roar·Hit·Death의 고유 프레임 수는 16장이지만, 각 상태에 공격용 타임라인이나 Idle 복귀를 기계적으로 적용하지 않는다.

# 6. 🎚 애니메이션 속도 변화

**Slow → Anticipation → Hold → Fast → Impact → Follow Through → Recovery**의 리듬을 사용한다.

가장 크게 몸을 비튼 Maximum Anticipation 자세에서 **약 0.15~0.25초 Hold**한다. 팔을 몸 뒤로 당기고 골반·허리를 회전하며 무릎을 굽힌 자세를 잠깐 유지한 뒤 빠른 공격으로 연결한다. Hold는 Anticipation 구간 안에서 배분하며 플레이어의 판단 시간을 제공한다.

# 7. 🎨 캐릭터 디자인 보존 원칙

기존 Idle·Walk에 나타난 설산 거인 디자인을 유지한다.

변경 금지: 얼굴, 체형, 팔·다리 비율, 손·발 크기, 털 구조의 임의 변경, 얼음 결정 개수·주요 위치의 임의 변경, 팔레트, 기존 갑옷·사슬 구조, 다른 캐릭터처럼 보이는 실루엣 재설계. 참조에 없는 갑옷·사슬을 새로 추가하는 의미가 아니다.

동작에 따른 관절 움직임, 원근 변화, 몸통 회전, 가려진 영역 노출, 털의 후행 움직임, 얼음 장식의 신체 추종, 자연스러운 압축·신장은 허용한다.

> 동작은 크게 만들지만 캐릭터 디자인과 프레임별 기준 배율은 변경하지 않는다.

# 8. 🔄 전체 보스전 흐름

`Dormant → 플레이어 진입 → Encounter Roar → Phase 1 → HP 50% 이하 → Phase Transition Roar → Scale Up + Red Eye Glow → Phase 2 → HP 0 → Death`

# 9. 🗣 Encounter — 전투 시작

플레이어 진입 → 일반 AI 정지 → Roar → Camera Shake / Roar SFX → Roar 종료 → Phase 1. 진입 즉시 공격하지 않는다.

Roar도 16프레임 전신 동작으로 제작한다.

**다리를 벌려 중심 잡기 → 무릎 굽힘 → 상체 낮춤 → 가슴·어깨를 뒤로 젖힘 → 양팔 크게 벌림 → 머리를 들며 Roar → 가슴·털·팔 후행 동작 → Idle**.

# 10. ❤️ Phase 1

HP **100%~50%**. 기본 크기, 푸른 눈, EyeGlow OFF. 강력하지만 비교적 느린 공격, 명확하고 큰 Telegraph, 긴 Follow Through, 확실한 반격 구간을 제공한다.

사용 패턴: 한손 내려찍기, 팔 휘두르기, 돌진, 얼음 가시, 양손 지면 강타.

# 11. 🔥 Phase 2

HP **50% 이하** → 현재 행동 종료 → 일반 AI 정지 → Phase Transition Roar → BossVisual Scale 증가 → Red Eye Glow 활성화 → Phase VFX → Phase 2.

| 요소 | Phase 1 | Phase 2 |
| --- | --- | --- |
| 크기 | 기본 | 증가 |
| 눈 | 푸른색 | 붉은 안광 |
| 안광 | OFF | ON |
| 패턴 | 기본 | 강화 |
| 연속 공격 | 적음 | 증가 |
| Ice VFX | 기본 | 강화 |

시각적 확대와 셀·피봇 규격은 별개다. Phase 2 연출을 위해 Sprite의 Pivot·PPU나 프레임별 크기를 변경하지 않는다.

# 12. 👁 붉은 안광 — 멀티스프라이트 오버레이

Phase 2용 전체 캐릭터 Sprite를 새로 만들지 않고 별도 EyeGlow SpriteRenderer를 Body 위에 겹친다.

```text
Boss
├─ BossVisual
│  ├─ Body
│  └─ EyeGlow
├─ HitBox
├─ HurtBox
└─ BossController
```

| Body 종류 | Body 규격 | EyeGlow 규격 |
| --- | --- | --- |
| Idle / Walk | 8장, 2048×1024 | 8장, 2048×1024 |
| 공격 / Roar / Hit / Death | 16장, 4096×1024 | 16장, 4096×1024 |

각 셀은 512×512다. Body와 EyeGlow의 **셀 크기·시트 배열·프레임 수·순서·Bottom Center Pivot `(0.5,0)`·PPU 50·Slice Offset/Padding·공통 Transform 기준**을 동일하게 유지한다.

Body 07이면 EyeGlow 07도 같은 셀 좌표에서 실제 눈 위치에 겹쳐야 한다. 눈만 있는 작은 불투명 영역을 기준으로 EyeGlow를 Trim하거나 재중앙 정렬하지 않는다. EyeGlow 자체의 중심에 피봇을 잡지 않는다. 두 Renderer의 상대 Transform에는 안광 위치 보정용 오프셋을 임의로 추가하지 않고, 프레임 안의 눈 좌표로 맞춘다.

Ready·Recovery에서 Body가 Idle을 참조하면 안광도 **Idle EyeGlow**를 참조한다. 단일 Animator Clip에서 두 SpriteRenderer를 같은 타이밍으로 제어하는 기존 원칙을 유지한다.

# 13. 💥 Pattern 01 — 한손 내려찍기

## Anticipation

반대쪽 다리로 체중 이동 → 무릎 크게 굽힘 → 골반 낮춤 → 몸통 뒤로 젖힘 → 공격 팔을 머리 위로 크게 들어 올림 → 팔꿈치·어깨 최대 후퇴 → Maximum Anticipation Hold.

실루엣만 보아도 내려찍기임을 알 수 있어야 한다.

## Attack

다리로 지면 밀기 → 골반 전진 → 상체 앞으로 내려옴 → 어깨 → 팔 → 손 → Ground Impact.

## Follow Through

손 지면 도달 → 상체 앞으로 쏠림 → 무릎 깊게 굽힘 → 몸 전체 낮아짐 → 관성 정리 → Idle.

Phase 2: Slam Impact 이후 Ice Spike 추가.

# 14. 🦾 Pattern 02 — 팔 휘두르기

큰 움직임의 기준이 되는 공격이다. **팔을 몸 뒤쪽까지 크게 당긴다.**

## Anticipation

발 간격 벌림 → 무릎 굽힘 → 뒷다리로 체중 이동 → 골반을 공격 반대 방향으로 회전 → 허리 비틀기 → 가슴·어깨 후방 회전 → 팔을 몸 뒤로 크게 당김 → 손도 몸 뒤로 이동 → Maximum Anticipation.

평상시 Idle과 확실히 다른 실루엣이어야 한다.

## Attack

뒷발로 지면 밀기 → 골반 빠르게 회전 → 허리 → 몸통 → 어깨 → 팔 → 손 → HIT. **몸이 팔을 끌고 오는 느낌**으로 제작한다.

## Follow Through

손이 공격 위치를 지나침 → 팔이 반대편까지 이동 → 상체 회전 → 앞다리에 체중 이동 → 몸 전체가 공격 방향으로 쏠림 → Idle.

Phase 2: 같은 Swing Animation으로 2연속 공격.

# 15. 🏃 Pattern 03 — 돌진

## Anticipation

상체 크게 낮춤 → 한쪽 발 앞으로 → 반대 발 뒤로 → 무릎 깊게 굽힘 → 골반 낮춤 → 팔 뒤로 배치 → 머리·어깨 전방으로 낮춤 → Hold. 곧 전방으로 돌진함을 명확히 예고한다.

## Attack

뒷다리 폭발적으로 펴기 → 몸 전체 전방 발사 → 전신을 기울인 상태로 돌진.

## Follow Through

돌진 종료 → 앞발로 지면 고정 → 상체가 관성으로 전진 → 팔·털이 뒤따름 → 중심 회복 → Idle.

Phase 2: 돌진 경로에 Ice Trail 생성.

# 16. ❄️ Pattern 04 — 얼음 가시

캐릭터 전용 Animation과 VFX를 조합한다. Body는 고유 16프레임이다.

## Anticipation

양발 넓게 고정 → 뒷다리에 체중 이동 → 무릎·골반을 깊게 낮춤 → 허리와 몸통을 크게 비틂 → 공격 팔을 지면 가까이 내밀고 **손바닥을 위로 펼침** → 반대 팔은 균형을 잡으며 뒤로 이동 → 낮게 웅크린 최대 전조에서 약 0.2초 Hold.

Idle 대비 몸 높이와 실루엣이 확실하게 달라야 한다. 바닥을 내려치는 준비 자세와 구분되도록 손바닥 방향과 아래에서 위로 이어질 큰 궤적을 보여준다.

## Attack

뒷다리로 지면 밀기 → 무릎 펴기 → 골반 전진·회전 → 허리·몸통 비틀림 풀기 → 어깨가 팔을 끌고 올라감 → 열린 손바닥을 지면 높이에서 얼굴 높이, **머리 위까지 크게 끌어올림** → 손의 상승과 함께 전방 Ice Spike가 솟아오름.

바닥 경고는 상승 직전부터 표시하고 판정은 실제 상승 구간에만 켠다. **얼음가시의 Body 동작은 위로 끌어올리는 소환이며, 양손 지면 타격 동작으로 되돌리지 않는다.**

## Follow Through

팔이 정점에 도달해도 바로 멈추지 않는다. 다리에서 전달된 힘으로 상체가 펴지고 뒤로 젖혀짐 → 팔·어깨·털이 상승 방향으로 뒤늦게 따라감 → 무릎으로 반동 흡수 → 팔을 크게 내려 정리 → 중심 회복 → Idle.

Phase 2: Ice Spike 개수·범위 증가, Telegraph 유지.

**최신 방향은 v01의 팔 상승 모티프 + v3.0의 큰 전신 동작·전조·16프레임 규격이다.** [v01](IceThorn_v01/Implementation.md)의 8프레임·1.8초 자산은 참고용으로 보존하고, 현재 [IceThorn v3](IceThorn_v3/Implementation.md)는 고유 16프레임·3초다. 기존 `BossIceThorn.prefab`을 사용하며 팔과 가시의 콜라이더를 클립 타이밍에 맞춘다. 피해 처리·자동 공격 선택은 사용자가 작성한다.

# 17. 💥 Pattern 05 — 양손 지면 강타

대표 강공격이며 가장 큰 움직임 중 하나로 제작한다.

## Anticipation

양발 크게 벌림 → 무릎 굽힘 → 골반 낮춤 → 가슴 펼침 → 몸통 뒤로 젖힘 → 양팔을 머리보다 훨씬 위로 들어 올림 → 양손 벌림 → Maximum Anticipation Hold.

## Attack

무릎 펴기 → 골반 전진 → 몸통 앞으로 접힘 → 양쪽 어깨 → 양팔 → 양손 → GROUND IMPACT.

## Follow Through

양손 지면 도달 → 상체 깊게 숙임 → 무릎 깊게 굽힘 → 몸 전체 충격 전달 → 팔·털·얼음 후행 동작 → Idle.

Phase 2: Shockwave 범위 또는 개수 증가.

# 23. 📐 멀티스프라이트 제작 규격 — Idle·Walk 기준

## 기준 파일과 적용 우선순위

- [Boss_Idle.png](../../Assets/04.Sprites/Boss/Boss_Idle.png) / [Import 설정](../../Assets/04.Sprites/Boss/Boss_Idle.png.meta)
- [Boss_Walk.png](../../Assets/04.Sprites/Boss/Boss_Walk.png) / [Import 설정](../../Assets/04.Sprites/Boss/Boss_Walk.png.meta)

현재 확인값은 셀 512×512, PPU 50, Bottom Center Pivot `(0.5,0)`이다. 모든 새 Body·EyeGlow는 이 기준을 따른다. 이후 두 기준 파일이 서로 다른 설정으로 바뀌면 임의로 한쪽을 골라 덮어쓰지 않고 차이를 확인한다.

## 8프레임 / 16프레임

| 항목 | Idle·Walk | 공격·Roar·Hit·Death |
| --- | --- | --- |
| 셀 | 512×512 | 512×512 |
| 전체 | 2048×1024 | 4096×1024 |
| 배열 | 4열×2행 | 8열×2행 |
| 고유 프레임 | 8 | 16 |
| Pivot | Bottom Center `(0.5,0)` | Bottom Center `(0.5,0)` |
| 피봇 픽셀 좌표 | `(256,0)` | `(256,0)` |
| 셀 기하학적 중심 | `(256,256)` | `(256,256)` |
| PPU | 50 | 50 |

**16프레임 공격은 8프레임 시트 두 장으로 나누지 않고 4096×1024 한 장으로 관리한다.** 실제 PNG 크기와 Unity Import 후 크기를 모두 확인해 축소된 텍스처를 최종 규격으로 오인하지 않는다.

## Unity Slice 기준

```text
Grid By Cell Size: 512 × 512
8프레임: 4 × 2
16프레임: 8 × 2

Pivot: Bottom Center (0.5, 0)
PPU: 50
Offset: 0, 0
Padding: 0, 0
Trim: 사용하지 않음
```

Unity Rect 좌표는 좌하단 원점이다. 두 종류 모두 윗행 Rect의 Y는 512, 아랫행 Y는 0이다. 각 열 X는 0,512,1024…로 증가한다. 열이 늘어도 셀 내부 기준은 바뀌지 않는다.

## 셀 중심과 피봇의 구분

- **셀 기하학적 중심 `(256,256)`**: 512×512 영역의 가운데. 불변의 셀 정보다.
- **Unity 피봇 `(256,0)`**: 셀 아래쪽 중앙, Idle·Walk와 같은 오브젝트 배치 기준이다.
- 그림 편집기의 좌상단 원점으로 표현하면 피봇은 **`(256,512)` 경계**다. 이는 마지막 픽셀 행 인덱스 511과 구분한다.
- 캐릭터의 불투명 영역 중심·무게중심·머리·골반은 동작에 따라 움직인다. 이를 피봇이나 셀 중심에 매번 강제로 맞추지 않는다.

## 접지선·몸 위치·오프셋

1. Idle·Walk와 같은 **셀 하단 접지 기준과 기준 자세의 몸 위치·크기**를 사용한다. 동일 셀 좌표로 실제 이미지를 겹쳐 비교한다.
2. Slice Offset `(0,0)`은 **격자 분할 시작 오프셋**이다. 그림의 투명 여백이 없다는 뜻도, 프리팹의 월드 위치나 모든 자식 Transform을 0으로 바꾸라는 뜻도 아니다.
3. 프레임마다 그림 전체를 바운딩 박스 중심으로 재정렬하거나, 손끝에 맞춰 Pivot을 이동하거나, 별도 Transform 오프셋으로 들썩임을 보정하지 않는다.
4. **발의 실제 디딤·들림, 무릎 굽힘, 골반 이동, 몸통 회전은 허용하고 적극 표현한다.** 모든 프레임에서 두 발의 픽셀을 고정하라는 규칙이 아니다. 지지하는 발의 접촉은 의도대로 유지하고, 다른 발의 움직임과 체중 이동을 구분한다.
5. 몸을 숙이거나 일어설 때 캐릭터 전체 이미지를 위아래로 옮겨 발이 뜨거나 지면에 파묻히게 하지 않는다. Death의 붕괴나 의도한 발 들림은 동작으로 표현하며 자동 하단 맞춤으로 지우지 않는다.
6. Ready·Recovery에는 기존 Idle Sprite를 같은 피봇·PPU·배치 기준으로 직접 참조한다. 전환 순간 그림 전체가 이동하거나 배율이 바뀌지 않아야 한다.
7. 큰 동작이 셀 밖으로 나가면 먼저 궤적·원근·포즈를 검토한다. 프레임별 축소나 잘라내기로 해결하지 않는다. 공통 규격 안에서 해결할 수 없으면 비교 자료를 바탕으로 규격 재검토가 필요함을 알린다.
8. Body와 EyeGlow는 같은 좌표계를 사용하며 눈의 실제 이동을 프레임 안에 기록한다. 공통 BossVisual 확대 시 함께 확대되도록 한다.

# 24. 📏 큰 동작 제작 기준

프레임 수만 늘려 완료 처리하지 않는다.

- **Anticipation:** Idle 대비 실루엣 변화가 명확하다.
- **Weight Shift:** 두 발에 같은 체중이 남은 정적인 자세를 반복하지 않는다.
- **Limb Travel:** 팔·손이 충분히 큰 궤적을 이동한다. 뒤로 당기면 몸 뒤쪽까지 확실히 간다.
- **Torso Rotation:** 허리·몸통·가슴·어깨가 함께 움직인다.
- **Follow Through:** 타격 이후에도 관성이 이어진다.

공통 피봇·정렬을 지키는 것과 전신을 고정하는 것은 다르다. Idle·Walk의 좌표계 안에서 큰 동작을 만든다.

7. 기존 디자인·체형·비율·재질·주요 특징을 유지한다.
8. 공격 부위만 움직이지 않고 체중 이동과 전신 회전을 포함한다.
9. Anticipation, Weight Shift, Follow Through를 크게 표현한다.
10. 팔을 당길 때 몸 뒤까지 당기고 골반·허리·몸통·어깨가 함께 움직인다.
11. 전조 자세만으로 다음 공격을 구분할 수 있어야 한다.
12. 공격은 빠르게, 전조와 Follow Through는 크고 묵직하게 표현한다.
13. Phase 2는 Body를 재사용하고 Scale, Red EyeGlow, VFX, 공격 로직으로 강화한다.
14. **피봇·PPU·Slice·접지·배치 기준은 실제 Idle·Walk를 따른다. Bottom Center `(0.5,0)`를 유지하고 셀 중심 `(256,256)`과 혼동하지 않는다.**
15. **공통 정렬은 동작 고정이 아니다.** 기준 좌표계를 유지하면서 발 디딤·체중 이동·전신 회전을 표현하며 프레임별 자동 보정으로 동작을 지우지 않는다.
