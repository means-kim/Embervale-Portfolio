# 시작·등반 복원 및 충돌 검토

2026-09-23 사용자 요청 반영. MapReview_v02 기준.

- BG_Climb_JoinGround_v01을 삭제 전 로컬 위치 (38.494816, 2.2665489, 0), Scale 1, 원본 geometry batch 31, order 32로 복원했다.
- 직전 작업에서 추가한 02_Climb SortingGroup을 제거하여 01_Start와의 기존 개별 렌더 순서로 복원했다. 두 구역 Transform 위치는 직전 작업에서 변경하지 않았으므로 임의 재배치하지 않았다.
- 방향키 이동 및 플레이어 추적 카메라는 유지했다.
- Unity에서 복원 실행·씬 저장·연결 바닥 표시를 확인했다. [좌표 검사](StartClimb_Restore_Validation.txt).

## 확인된 충돌 불일치 원인

1. build_map_review.mjs의 시작 바닥은 Y=0인 수평선 하나다. 바위와 눈의 실제 굴곡을 추적하지 않는다.
2. 등반 발판은 HTML의 surface 계수로 높이를 추정하고 폭의 8~92% 사이를 수평선으로 만든다. 실제 PNG의 밟는 윗면과 끝을 기준으로 만든 선이 아니다.
3. 현재 시작 바닥은 X=0~41.481, Y=0이고 입구 발판은 X=35.774~80.375, Y=-0.498이다. 겹침 구간과 약 0.50유닛 높이 차이가 있다. 이는 캐릭터 높이 1.68의 약 30%다. 실제 그림과 맞는 단차인지 재조정이 필요하다.
4. Art와 Gameplay는 별도 Transform이며 발판별 연결 참조가 없다. 그림만 옮기면 충돌선은 따라가지 않는다.
5. ReviewTerrain.OnEnable은 저장된 points로 EdgeCollider2D.points를 덮어쓴다. Edit Collider만으로 고친 선은 재활성화/재로드 때 초기화될 수 있다.

## 권장 수정 방향 (아직 미적용)

- 지면의 실제 착지 윗면을 기준으로 간소화한 꺾은선을 만든다. 미세한 바위·눈 요철까지 추적해 이동이 걸리게 만들지 않는다.
- 일반 발판은 EdgeCollider2D, 측면까지 막아야 하는 두꺼운 지형은 단순한 PolygonCollider2D로 준비한다. 아래에서 통과해야 하는 발판은 별도로 원웨이 동작을 선택한다.
- 발판별 공통 루트 아래 Art와 Collision을 나눠 두어 이동·크기 조절 시 함께 움직이도록 한다. 장식 배경은 이 묶음에 넣지 않는다.
- 충돌 좌표의 원본을 하나로 정한다. 현 구조를 유지한다면 ReviewTerrain.points를 편집하고 반영해야 하며, 수동 Collider 편집을 선택한다면 자동 덮어쓰기를 제거해야 한다.
- 입구는 시작 바닥→연결 바닥→등반 바닥의 윗면을 연속적으로 맞추고 불필요한 겹침 선을 없앤다.
- 눈은 별도 아트로 유지하고 바위 지형 충돌을 기준으로 삼는다. 캐릭터 캡슐 바닥과 실제 발 위치도 함께 비교한다.

이번 요청에서는 복원과 원인 조사까지만 진행했다. 충돌선 재작성 및 발판 구조 변경, 전체 이동 검증은 아직 진행하지 않았다.
