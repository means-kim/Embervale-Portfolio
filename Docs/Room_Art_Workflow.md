# 룸 구조와 맵 아트 제작 합의

2026-09-22. 사용자와 검토 후 프로젝트 지침으로 기록했다.

## 구조와 역할

룸 단위 관리를 우선 검토한다. 하나의 연결된 세계를 여러 Unity 씬으로 나눌 수 있으며, 룸 하나가 화면 하나라는 뜻은 아니다. 시작→등반→보스 통로→보스전1→낙하→보스전2는 구역 연결 기준이고 최종 씬 수는 미정이다.

Gameplay는 충돌·게이트·위험·상호작용·적·트리거, Art는 원경·중경·근경·플레이 지형·전경·안개로 역할을 나눈다. 구체적인 Room.cs·RoomGate·Z 숫자·Tilemap 구조는 우리 프로젝트의 설계 후보다. 세 참고 작품이 모두 정확히 그 구조라는 사실로 기록하지 않는다.

Unity 배치·조립은 사용자가 담당하고 Codex는 소재 제작·수정·배치 검토를 보조한다. 이 합의는 코드나 씬 자동 생성 요청이 아니다.

## 작업 순서

1. 컨셉으로 분위기·구역 연결·시각적 기준을 잡는다.
2. 사용자 담당 임시 플레이 지형과 캐릭터·카메라로 점프·착지·통로·전투 공간을 확인한다.
3. 검증된 플레이 지형에 맞춰 바닥·벽·발판 그림과 별도 눈 덮개를 만든다.
4. 원경·성·숲·고목 등을 겹쳐 배치하고 플레이 공간 가림과 가독성을 확인한다.

2번이 미정인 동안 장식 소재 제작은 가능하다. 다만 그림에 맞춰 점프 거리나 카메라를 억지로 확정하지 않는다. HTML 합성은 아트 검토이고 실제 플레이 검증을 대체하지 않는다.

## 소재 역할

| 소재 | 후보 역할 | 주의 |
|---|---|---|
| 하늘·달·설산 | BG_Far | 전체 맵을 덮는 한 장으로 확정하지 않음 |
| 먼 성·다리·절벽 | BG_Mid의 먼 쪽 | 풍경용이므로 자동 충돌 생성 안 함 |
| 숲 | BG_Mid | 개별 나무 이동이 필요하면 분할 |
| 고목·가지 | BG_Near 또는 FG | 캐릭터 앞뒤 역할에 따라 분할 가능 |
| 바닥·벽·발판 그림 | Playfield | 검증된 충돌 지형에 맞춤 |
| 안개 | Atmosphere | 관리 폴더와 실제 렌더 순서는 구분 |

Sorting Layer/Order, Z, 패럴랙스 속도를 별개로 정한다. 충돌 지형은 타일맵만으로 제한하지 않으며, 별도 발판·이동 물체에는 해당 역할에 맞는 콜라이더가 필요할 수 있다. Additive 로드는 스트리밍 구현의 수단이지 완성된 시스템이 아니다.
